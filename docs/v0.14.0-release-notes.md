# VoteKit v0.14.0

VoteKit v0.14.0 separates voting credentials generated from ballots actually
distributed, producing a more accurate and auditable participation rate.

## Changes

- Assigned election administrators can report the number of ballots distributed
  from the election admin page.
- Every adjustment requires a reason and records the previous value, new value,
  generated credential count, administrator and timestamp.
- Corrections append to immutable adjustment history rather than overwriting it.
- Participation uses ballots distributed as its denominator.
- Online results, JSON, PDF and CSV disclose both counts, the denominator source,
  participation rate and full adjustment history.

## Safety and compatibility

- Distribution reporting does not change voting codes, voter-roll entries,
  ballots, receipts or declared results.
- Values below ballots already cast or above generated credentials are rejected.
- Existing elections receive no automatic adjustment. Until an administrator
  reports distribution, VoteKit retains the generated-credential denominator
  and labels it as an assumption.
- The additive database table is backward compatible with the prior release.

## Verification

- Route coverage verifies validation, audit logging, participation calculation,
  default compatibility, CSV disclosure and preservation of correction history.
- The complete automated suite, lint, type-check, production build, dependency
  audit and production migration rehearsal must pass before release.
