# VoteKit v0.13.0

VoteKit v0.13.0 adds optional full preference distributions for ranked-choice
elections while preserving the first majority as the only official result.

## Changes

- Election creators can choose to continue an IRV count to a final-two
  preference distribution after the winner is declared.
- The option is off by default, persists through setup drafts and is visible in
  review and private proofing pages.
- Official winner and decisive round are frozen at the first majority.
- Later rounds are explicitly labelled `Supplementary distribution` in the web
  result, PDF report and CSV export and cannot replace the declared result.
- Owners and Returning Officers can create an immutable audited full preference
  distribution from a closed ranked-choice question's frozen ballots without
  changing its original setup.
- Existing countback and audited tie-decision rules also protect supplementary
  exclusions. An unresolved supplementary tie pauses the reporting count without
  affecting the already-declared winner.
- Source ballots, algorithm settings and result output remain bound by SHA-256
  fingerprints.

## Data and compatibility

- Adds `questions.continue_after_majority` with a safe default of `0`.
- Existing elections retain stop-at-majority behaviour.
- The migration does not rewrite elections, questions, ballots, voter records,
  receipts or prior count runs.
- Previous code safely ignores the additive column if code rollback is required.

## Verification

- Unit and integration coverage verifies the official majority, post-majority
  transfers, exhausted ballots, final-two tally, supplementary ties, setup
  persistence, permissions, audit records and HTML/PDF/CSV labelling.
- The migration is rehearsed against a private copy of the production database,
  with table aggregates and integrity preserved.
