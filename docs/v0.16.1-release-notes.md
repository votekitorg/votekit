# VoteKit v0.16.1 — One-click public-poll confirmation

At the organiser’s request, the confirmation email now has one green **Confirm ballot** link. Following it automatically confirms the ballot on the landing page; no second confirmation button is required. The page shows completion only after the server accepts confirmation. Temporary failures show an error and a retry action; expired or missing links do not show success.

The link’s secret remains in the URL fragment, is removed from the address bar on arrival and is submitted via the existing CSRF-protected POST. A plain page GET does not confirm a ballot. Email security scanners that execute page JavaScript may trigger confirmation: the previous explicit-button scanner protection is intentionally removed for this simpler flow. Existing token expiry, first-confirmation-wins policy, idempotence, privacy finalisation and result counting are unchanged.

Verification: 185 automated tests passed (one pre-existing skipped test), lint/type checks/build passed. Focused browser checks covered automatic confirmation without a second button, exactly one initial POST, repeated links, failed request and retry, expired/missing links, fragment removal and mobile/desktop layouts. No real confirmation emails were sent during testing.
