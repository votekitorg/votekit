# VoteKit v0.15.0 - Post-election workflow and qualification update

## Voter and administrator experience

- Existing-account invitations use a single existing-password field. Password
  creation and confirmation are shown only when needed for a new account.
- Submission errors remain visible beside the review controls, including when
  voting ends while a ballot is open. Failed requests retain the voter's choices.
- Mobile ballots show question numbers, required indicators and answered progress.
  Missing answers have a visible summary and receive focus/scroll guidance.
- Ranked ballots start empty. Tap options in preference order, then use accessible
  reorder/remove controls. Compulsory ballots require all options to be ranked.
- Expected voting closure uses a neutral “Voting has closed” screen. Missing links
  and technical failures have distinct wording; finalised elections open results.
- Administrator screens distinguish voting ended from finalised results. Actions
  read “Close Voting Early” or “Finalise and Count Votes” according to the deadline.

## Audited deadline extensions

- Authorised election managers can extend voting before finalisation starts,
  including after the original deadline. Extensions never change the electorate.
- A public reason is mandatory. History records old/new deadlines, administrator
  and timestamp, and appears in admin/voting/results views and PDF/CSV exports.
- Reject shortening, invalid dates, stale edits and extensions of finalised or
  already-finalising elections. No automatic notification messages are sent.
- Encrypted elections retain their original authenticated manifest and recovery
  kit. The operational deadline is extended separately with an audited history.

## Seek Further Candidates

- Optional qualification rule on single-winner Condorcet questions, configured
  before publication. Choose a reference option/label, an exact fraction and a
  strict “more than” or inclusive “at least” comparison. Default: more than 2/3.
- Ranked options beat omitted ones; omitting both contributes neither side.
  Zero expressed pairwise preferences does not qualify a candidate.
- Failed candidates and the reference option are excluded before the existing
  Condorcet/Schulze selection among qualifying candidates. No qualifiers means
  nobody is elected; unresolved ties remain ties.
- Every candidate's qualification counts and pass/fail outcome appear in online
  results, PDF and CSV. This release does not introduce multi-seat STV rules.
- Condorcet recounts retain the qualification rule. IRV alternative counts are
  unavailable for these questions because they would bypass that rule.

## Maintenance and compatibility

- Targeted security dependency updates, including Next.js 15.5.26, Vitest 4.1.11,
  sharp 0.35.4 and affected browser/CSS tooling.
- Additive schema changes only. No existing election's deadline, SFC settings,
  ballots, voting credentials or declared results are changed automatically.
- CiviCRM integration is deferred and is not included.

## Rollback note

Before rolling back below v0.15.0, check for newly configured SFC elections or
deadline extensions. Older code cannot enforce SFC qualification or reconstruct
extended encrypted manifests correctly. Prefer a forward fix if either feature
has been used; do not reset a live election database to remove these records.

See post-election-update-design.md for the acceptance and verification plan.
