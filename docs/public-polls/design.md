# Public poll MVP

Authorised by Jud, 29 September 2026: public link, ranked preferences, self-declared membership, email after ballot submission, all/confirmed/confirmed-member results. Small launch window. This adds the feature, not permission to launch a leadership poll or contact real participants during testing.

## Scope and workflow
Independent poll tables/routes preserve all existing election modes. Owner/RO creates and owns a draft; Owner can manage all. Explicit publish freezes question/options/dates. Public participant ranks at least one option, declares membership (yes/no/prefer not), supplies email and consents. Email contains no choices, only a confirmation link. Opening the email link loads a landing page that automatically sends the confirmation POST and displays completion, with no second button (updated at Jud’s request in v0.16.1). A plain HTTP GET does not confirm; scanners that execute JavaScript may confirm. Errors never show success and allow retry. Submission close and confirmation close are separate; links last up to 48h bounded by confirmation close. Admin finalises after confirmation closes; then publishes aggregate results. No live preferences or ballot export.

First version: one optional-preference ranked question, Condorcet with Schulze fallback using existing tested counter. Ranked candidates beat omitted candidates; omitted candidates tie. Display first preferences, pairwise comparison and winner/tie. Public poll is participation mode, not the mathematical counting method. Further question types deferred.

## Duplicate policy
Case-insensitive trimmed email matching, without provider-specific dot/plus stripping. One accepted ballot per address in all and confirmed totals. First unconfirmed submission initially accepted. Up to five pending claims per address per hour let a real owner confirm their intended submission despite an earlier spoofed submission. First successful confirmation wins and replaces the earlier accepted unconfirmed ballot. Later confirmations/re-submissions cannot overwrite it. Still not one-person-one-vote. Shared IP is not proof of duplication. Rate limits contain bursts; no discretionary deletion based on preferences.

## Privacy model
Temporary-link confidentiality, not operator-proof anonymity. Ballot rows contain random IDs, rankings, membership, accepted/confirmed flags, no email/IP/timestamps. Claim rows contain HMAC email keys, hashed random confirmation tokens and AES-256-GCM ciphertext containing ballot ID/email/IP/timestamps/expiry. A random per-poll key lives in a 0700 directory with 0600 files OUTSIDE database backups. Submission and confirmation fail if the privacy key is unavailable. Results require completion of privacy finalisation. Do not back up these keys: losing a key prevents pending confirmations but does not lose rankings. No email, IP, token or ranking in application audit/error messages. Fragment confirmation tokens, no-referrer/no-store pages, no analytics.

Finalisation transaction rebuilds accepted ballots in random order with fresh IDs, removes claim rows/rate data and changes status to sealing. Key deletion follows; retry is safe after a crash. Only then finalised status/results are available. DB backups contain encrypted links but not keys; restoration of a previously sealed poll must never recreate a key or permit reopening. Host filesystem snapshots/key backups and network/transport logs are separate residual risks; do not promise operator-proof anonymity. Verified on 29 September 2026: the managed backup job copies only SQLite, not the separate key directory. Email provider receives address and link, never rankings. No per-voter admin export.

## Verification checklist
Migration additive/idempotent and production-copy preservation; role/ownership/CSRF isolation; malformed/oversize choices/emails rejected; all date/status boundaries; independent poll tokens; first confirmation wins, pending spoof does not block legitimate claim; duplicate counts; delivery failure/retry; token expiry/reuse; rate limits; raw identity absent from primary rows/audits; key deletion/seal retry; all three result subsets; no pre-publication results; browsers desktop/mobile; existing full suite/build/lint/type checks.
