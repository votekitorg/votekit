# Ballot Distribution Reporting

## Decision

VoteKit distinguishes voting credentials generated by the system from ballots
actually distributed to electors. Election administrators may report the latter
with a mandatory reason. Participation is ballots cast divided by ballots
distributed.

The setting is reporting-only. It never creates, revokes, enables or disables a
voting credential and does not change a ballot or declared result.

## Data and audit model

Each change appends a row to `ballot_distribution_adjustments` containing:

- the election;
- the previous and updated distribution figures;
- the number of generated credentials at the time;
- the administrator-supplied reason;
- the administrator identity and timestamp.

The normal application workflow has no update or delete operation for these
rows. A matching `admin_audit_log` event provides the organisation-wide audit
record. If no adjustment exists, VoteKit preserves its previous behaviour by
assuming every generated credential was distributed and clearly labels that
assumption.

## Validation and authority

- Owners, Returning Officers and election Admins assigned to the election may
  record an adjustment. Observers remain read-only.
- The figure must be a whole number at least equal to ballots already cast and
  no greater than credentials generated.
- A reason is mandatory and limited to 500 characters.
- Archived elections must be restored before adjustment.
- Corrections append another record rather than replacing history.

## Reporting

The admin screen, public result, JSON API, PDF report and CSV export use the same
shared participation model. Published results show credentials generated,
ballots distributed, the source of the denominator, the participation rate and
the complete adjustment history.

## Compatibility and release

The schema migration creates one additive table and does not seed or alter any
existing election. Existing elections therefore retain their current figures
until an authorised administrator explicitly records an adjustment. Previous
application versions safely ignore the new table if code rollback is required.
